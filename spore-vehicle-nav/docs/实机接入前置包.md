# 实机接入前置包

> 状态：2026-08-30 已完成树莓派基础静止接入与重启复验；现场运动、正式建图、精度、failsafe、RTK、采样器和相机仍未完成。  
> 安全边界：Web 控制台在实机接入前只读订阅；任何 `/cmd_vel`、任务启动、返航、取消或软件停车操作必须经现场负责人明确授权。软件停车不是物理急停。

## 1. 连接参数与话题表

| 项目 | 当前值/建议 | 消息类型 | 目标频率/超时 | 接入说明 |
|---|---|---|---|---|
| ROS 域 | `ROS_DOMAIN_ID=77` | 环境变量 | 全部节点一致 | 已有车辆部署基线；现场先核对，不要在 Web 中暴露。 |
| rosbridge 地址 | `ws://<VEHICLE_HOST>:9091`（或车辆实际 IP） | WebSocket | 已验证监听 9091 | 控制台仍需用户显式点击连接；仅接收适配后的契约对象，运动控制默认锁定。 |
| 融合位姿 | `/odometry/filtered` | `nav_msgs/Odometry` | 约 20 Hz；1.0 s | Web 主位姿；超时后标记 stale。 |
| 轮式回退位姿 | `/odom` | `nav_msgs/Odometry` | 约 20 Hz；1.0 s | 仅作为融合位姿缺失时的降级来源。 |
| 雷达 | `/scan` | `sensor_msgs/LaserScan` | 约 11–12 Hz；0.5 s | 前向 ±90°，`<0.5 m` 为软件安全门条件；缺失/过期在车端零速度。 |
| 任务状态 | `/mission/status` | `std_msgs/String`（JSON） | 1 Hz 心跳 + 事件 | 必须适配为契约 `mission_status/mission_event` 1.0。 |
| 电池 | `/battery_state` | `sensor_msgs/BatteryState` | 现场实测频率 | 适配电压、电量、低电量。 |
| 诊断 | `/diagnostics` | `diagnostic_msgs/DiagnosticArray` | 现场实测频率 | 适配等级、消息、超时。 |
| RTK | `/fix`、`/gps/rtk_status` | `sensor_msgs/NavSatFix`、待冻结 | 现场实测频率 | 当前未接入；状态只能为 `unavailable`，直至负责人冻结接口。 |
| 采样器 | `/sampler/status` | 待冻结 | 现场实测频率 | 只接受 `ready/working/completed/failed/timeout` 及故障码。 |
| 相机 | `/image_raw` 或 RTSP | `sensor_msgs/Image` / RTSP | 现场实测频率 | 先做只读画面确认，不影响导航。 |
| 车辆速度 | `/cmd_vel` | `geometry_msgs/Twist` | 10 Hz；底盘看门狗 0.30 s | 仅现场低速授权后启用；无授权时保持发布者锁定。 |

## 2. 接入顺序（先只读，后低速）

1. 现场完成实体急停、人员隔离、轮胎离地/空旷区、速度限制和操作者分工检查；没有现场负责人不得继续。
2. 在树莓派 ROS 环境中核验 `ROS_DOMAIN_ID=77`，再执行只读 `ros2 topic list`、`ros2 topic hz /odom /odometry/filtered /scan` 和每个关键话题一次 `echo --once`。
3. 核对 TF 链 `map → odom → base_footprint → base_link → laser_link`，并记录地图版本、路线文件 SHA-256、起始位姿、时间和操作者。
4. rosbridge 由 `spore-rosbridge.service` 自动启动；Web 使用 `ws://<VEHICLE_HOST>:9091`，先只观察数据新鲜度、时间戳、坐标系、RTK `unavailable` 标志和任务状态适配；不得启用运动控制。
5. 分别接入电池、诊断、RTK、采样器和相机，每增加一种来源均保存原始话题样本与适配后的契约 JSON；未知字段或状态保持拒绝，不做猜测映射。
6. 只有完成现场安全评审后，才按既有 RUNBOOK 的低速测试执行；每次命令都需有物理急停在位和独立观察人。

## 3. 最小适配样例

所有适配结果必须包含 `contract_version: "1.0"`、`source_mode: "rosbridge"`、`field_id`、`mission_id`、`route_id` 和 `timestamp_ms`。以下是形状示例，不是现场实测数据。

```json
{
  "kind": "robot_telemetry",
  "rtk": { "state": "unavailable", "age_ms": null, "satellites": null },
  "sampler": { "state": "unavailable", "sample_id": null, "fault_code": null }
}
```

RTK 接入后把 `state` 限定为 `single`、`float` 或 `fix`；采样器接入后把 `state` 限定为 `ready`、`working`、`completed`、`failed` 或 `timeout`。相机仅记录来源、帧率、分辨率和时间戳；不要将画面或设备网络凭据写入会话导出文件。

## 5. 接入完成判据

本次已完成“网络/SSH + 传感器节点 + rosbridge + 静止只读数据”的基础接入验收，但不等同于完整实机验收。只有同时具备原始记录、只读数据核验、现场低速结果和安全负责人确认，才可在总基线中将相应硬件/性能状态改为“已验证”。定位精度、物理急停、障碍停车和采样联动均须单独实测，不能由本次静止验收或离线质量门推断。
