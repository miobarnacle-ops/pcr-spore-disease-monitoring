# ICM20948 融合与室内二维建图操作指南

本文档把 STM32 板载 ICM20948 的本地 EKF 融合、YDLIDAR X3 Pro 二维建图、
rosbag 录制和地图保存整理为一套连续的实车操作流程。

当前融合只使用轮式里程计的平移速度和 ICM20948 的偏航角速度，不使用加速度、
姿态四元数或磁力计。CMP10A 和北斗属于后续室外全局定位链路，不在本流程中接入。

本流程不会自动发布 `/cmd_vel`。启动底盘、雷达、EKF、SLAM 和 RViz 后，小车仍会
保持停车，只有操作者另行启动键盘遥控并按键后才会运动。

## 1. 数据链和 TF 分工

主要话题：

| 话题 | 来源 | 用途 |
|---|---|---|
| `/odom` | STM32 底盘驱动 | 编码器前向速度和零横向速度约束 |
| `/imu/data_raw` | STM32 底盘驱动 | 未修改的 ICM20948 原始数据 |
| `/imu/data_calibrated` | 零偏校准节点 | 启动静止10秒后校正的角速度 |
| `/odometry/filtered` | `robot_localization` EKF | 融合后的连续本地里程计 |
| `/scan` | YDLIDAR X3 Pro | SLAM 激光扫描 |
| `/map` | SLAM Toolbox | 二维占据栅格地图 |

融合建图时的 TF 链应为：

```text
map -> odom -> base_footprint -> base_link -> laser_link
```

TF 只能由一个节点负责：

- SLAM Toolbox 发布 `map -> odom`；
- EKF 发布 `odom -> base_footprint`；
- `robot_state_publisher` 发布车体内部静态或关节 TF；
- 底盘驱动仍发布原始 `/odom`，但其 `publish_tf` 会被组合启动文件关闭。

不要同时运行原始 `spore_patrol_bringup hardware.launch.py`、原始
`spore_patrol_slam mapping.launch.py` 和本文的融合启动文件，否则可能重复占用
STM32 串口或重复发布 TF。

## 2. 首次安装和编译

只在首次使用或依赖变化后执行安装：

```bash
cd ~/spore_patrol_ws
sudo apt-get update
sudo apt-get install -y \
  ros-humble-robot-localization \
  ros-humble-slam-toolbox \
  ros-humble-nav2-map-server

source /opt/ros/humble/setup.bash
source tools/ydlidar_env.sh
colcon build --symlink-install --packages-up-to spore_patrol_localization
source install/setup.bash
```

工作区固定使用 Ubuntu 系统盘的 `~/spore_patrol_ws`。不要再从
`/media/brown/新加卷*` 下的旧副本编译或启动。

## 3. 每次上车前检查

电脑接入电源，确认底盘和雷达分别被识别：

```bash
ls -l /dev/ttyACM0 /dev/ydlidar
lsusb
```

预期底盘为 `/dev/ttyACM0`，雷达稳定名称为 `/dev/ydlidar`。若设备不存在，先解决
USB、供电或 udev 问题，不要反复启动 ROS 节点。

确认当前没有遗留的底盘、雷达、SLAM、键盘遥控或 Nav2 进程：

```bash
pgrep -af "base_driver|ydlidar|slam_toolbox|teleop_twist|nav2"
```

若有上一轮程序，回到对应终端按 `Ctrl+C` 正常结束。落地运动时必须有人跟车，并能
立即关闭电机使能或总电源。

## 4. 先单独验证轮速和 ICM20948 融合

终端一：

```bash
cd ~/spore_patrol_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 launch spore_patrol_localization hardware_localization.launch.py \
  port:=/dev/ttyACM0 \
  lidar:=false \
  rviz:=true
```

该命令启动机器人模型、STM32底盘驱动、IMU零偏校准、EKF和RViz，不会主动
让车运动。启动后保持小车完全静止10秒，直到终端输出
`Gyro bias calibration complete`；检测到转动时计时会自动重置。

终端二检查数据：

```bash
cd ~/spore_patrol_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 topic hz /odom
ros2 topic hz /imu/data_raw
ros2 topic hz /imu/data_calibrated
ros2 topic hz /odometry/filtered
ros2 topic echo /imu/data_raw --once
ros2 topic echo /imu/data_calibrated --once
ros2 topic echo /odometry/filtered --once
ros2 run tf2_ros tf2_echo odom base_footprint
ros2 topic echo /diagnostics --once
```

校准完成后，预期 `/odom`、`/imu/data_raw`、`/imu/data_calibrated` 和
`/odometry/filtered` 均约为20 Hz。小车静止时，
融合位姿不应持续快速旋转；缓慢人工转动车体或使用低速遥控转向时，
`angular_velocity.z` 和融合后的偏航方向应随之变化。

当前STM32协议没有输出有效姿态四元数和磁力计。校准节点保留 `/imu/data_raw`，
对静止窗口内三轴角速度求平均，然后按
`校正角速度 = 原始角速度 - 静止平均零偏` 处理后续数据。EKF只融合
`/imu/data_calibrated` 的Z轴角速度。加速度容易受到电机、底盘悬挂和地面振动影响，
当前也不参与融合。这是有意的配置，不是 IMU 功能缺失。

完成单独检查后，在终端一按 `Ctrl+C`，等待所有节点退出，再进入融合建图。不要让
单独融合启动和融合建图启动同时占用 `/dev/ttyACM0`。

## 5. 启动融合建图

终端一：

```bash
cd ~/spore_patrol_ws
source /opt/ros/humble/setup.bash
source tools/ydlidar_env.sh
source install/setup.bash

ros2 launch spore_patrol_localization mapping_localization.launch.py \
  base_port:=/dev/ttyACM0 \
  lidar_port:=/dev/ydlidar \
  rviz:=true
```

这个入口一次启动底盘、雷达、机器人模型、IMU零偏校准、EKF、SLAM Toolbox
和RViz。每次启动仍需先静止10秒，校准完成后才能开始录包和移动。RViz刚
启动的前几秒可能提示 `map` 不存在；收到第一帧可用雷达和里程计后应自动恢复。

终端二检查：

```bash
cd ~/spore_patrol_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 topic hz /scan
ros2 topic hz /odom
ros2 topic hz /imu/data_raw
ros2 topic hz /imu/data_calibrated
ros2 topic hz /odometry/filtered
ros2 topic hz /map
ros2 run tf2_ros tf2_echo map base_footprint
```

当前实测参考值：

- `/scan` 约 12 Hz；
- `/odom`、原始与校正IMU、`/odometry/filtered` 约20 Hz；
- `/map` 通常每约 2 秒更新一次。

频率短时波动可以接受，但不能长时间为零，也不应持续出现串口 checksum、TF 或
scan matching 错误。

## 6. 先录包，再移动

确认融合建图正常后，在终端三开始录包：

```bash
cd ~/spore_patrol_ws
source /opt/ros/humble/setup.bash
source tools/ydlidar_env.sh
source install/setup.bash

tests/slam/record_mapping_bag.sh
```

脚本会保存 `/scan`、原始 `/odom`、`/imu/data_raw`、`/imu/data_calibrated`、
融合 `/odometry/filtered`、TF、地图、诊断、电池和 `/cmd_vel`，便于离线复现与比较。
开始录制后先让小车静止约 10 秒。

终端四启动键盘遥控：

```bash
cd ~/spore_patrol_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 run teleop_twist_keyboard teleop_twist_keyboard \
  --ros-args \
  -p speed:=0.08 \
  -p turn:=0.20
```

在键盘遥控终端中按提示的按键控制，鼠标焦点必须位于该终端。建议：

1. 从有明显墙角、门框或纸箱的位置开始；
2. 沿房间或走廊边缘低速行驶；
3. 转弯使用连续小角速度，不要高速原地甩尾；
4. 让雷达反复看到已经建过的墙角或固定物体；
5. 绕一圈回到起点，再静止约 10 秒等待闭环优化。

避免人群围绕雷达移动、镜面玻璃、大面积空旷区域、雷达后方紧跟电脑和轮胎明显
打滑。首轮路线控制在 3～5 分钟，先保证数据链稳定，不追求大范围。

## 7. 保存地图并正常结束

小车回到起点并静止后，保持融合建图程序运行，在新终端执行：

```bash
cd ~/spore_patrol_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

tools/save_slam_map.sh indoor_03
```

地图名称只能包含字母、数字、下划线和连字符。脚本不会覆盖已有同名地图，重测时
使用 `indoor_04` 等新名称。正常会生成：

```text
maps/indoor_03.yaml
maps/indoor_03.pgm
maps/indoor_03.posegraph
maps/indoor_03.data
```

`.yaml + .pgm` 用于后续 Nav2 静态地图；`.posegraph + .data` 用于继续建图或
SLAM Toolbox 定位。

结束顺序：

1. 地图保存成功后，在键盘遥控终端停止操作；
2. 在录包终端按一次 `Ctrl+C`，等待 rosbag2 正常写完索引；
3. 最后在融合建图终端按 `Ctrl+C`；
4. 不要直接关闭录包终端或在写索引时强制断电。

录包结果位于：

```text
tests/results/时间_mapping/rosbag/
```

## 8. 验收标准

### IMU 和 EKF

- 校准完成后四个里程计/IMU输入输出话题持续发布，频率接近20 Hz；
- `/diagnostics` 中 IMU gyro bias 状态为 `calibrated`；
- `/odometry/filtered` 的时间戳持续更新；
- 静止时融合航向没有明显快速漂移；
- 左转、右转时 IMU Z 轴角速度符号和 RViz 中转向一致；
- TF 中只有一条 `odom -> base_footprint`；
- 终端没有持续出现 EKF 时间戳、协方差或传感器超时错误。

### 二维地图

- 墙面主要是单层清晰轮廓，而不是多条平行重影；
- 回到起点后，起点附近墙角能重新对齐；
- 地图不会随小车原地旋转而整体扭曲；
- `/scan`、里程计、IMU 和 USB 连接全程不中断；
- PGM、YAML、posegraph、data 和 rosbag 均已保存。

融合后的里程计通常能改善转弯期间的短时航向估计，但不能消除轮胎打滑、雷达支架
晃动、环境几何特征不足或 USB 丢帧。地图不好不等于一定是 EKF 参数错误。

## 9. 常见问题

### 找不到 `robot_localization` 或 `ekf_node`

```bash
sudo apt-get install -y ros-humble-robot-localization
source /opt/ros/humble/setup.bash
source ~/spore_patrol_ws/install/setup.bash
```

### `/odometry/filtered` 没有数据

依次检查：

```bash
ros2 node list
ros2 topic hz /odom
ros2 topic hz /imu/data_raw
ros2 topic hz /imu/data_calibrated
ros2 topic info /odometry/filtered --verbose
ros2 topic echo /diagnostics --once
```

原始 `/odom` 或 `/imu/data_raw` 停止时先排查STM32串口。只有
`/imu/data_calibrated` 不发布时，应保持车体静止并查看校准节点日志；运动会使
10秒窗口重新开始。需要主动重校准时执行：

```bash
ros2 service call /imu_bias_calibrator/recalibrate std_srvs/srv/Trigger "{}"
```

### `/dev/ttyACM0` 打不开

检查设备是否存在、用户是否属于 `dialout`、是否已有旧进程占用串口：

```bash
ls -l /dev/ttyACM0
groups
pgrep -af "base_driver|hardware_localization|mapping_localization"
```

### TF 重复或机器人模型跳动

通常是同时启动了原始硬件入口和融合入口。停止全部相关终端，只保留
`hardware_localization.launch.py` 或 `mapping_localization.launch.py` 其中一个。

### RViz 报 `Unable to create glx context`

当前硬件和建图启动文件已为这台混合显卡电脑强制选择 Mesa。先确认使用的是系统盘
工作区并重新 source：

```bash
cd ~/spore_patrol_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```

不要从旧的 `/media/brown/新加卷*` 安装空间启动。

### 直线墙出现双层或转弯后地图扭曲

- 直线双层：优先检查轮式里程计尺度、雷达支架和 USB 丢帧；
- 转弯扭曲：检查 ICM20948 Z 轴符号、原地旋转标定和雷达 yaw；
- 空旷处漂移：缩小范围，并增加纸箱、墙角等固定几何特征；
- 局部突然错位：检查轮胎打滑、人员遮挡和雷达扫描是否中断。

## 10. CMP10A 和北斗的接入边界

CMP10A 后续应使用独立的 `cmp10a_link` 坐标系和绝对航向话题。接入前必须验证：

- 安装方向和坐标轴；
- 时间戳、更新频率和通信延迟；
- 航向协方差；
- 电机、24 V 电源、DC-DC、电脑和载荷全部工作时的磁干扰；
- 与 ICM20948 角速度及北斗运动航向的一致性。

在这些数据没有测清前，不要把 CMP10A 和 ICM20948 当作两个等价角速度源同时
融合。当前室内建图继续使用 STM32 板载 ICM20948；CMP10A 留给后续室外绝对航向、
GNSS/RTK 和全局定位。
