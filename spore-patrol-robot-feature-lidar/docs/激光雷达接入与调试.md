# YDLIDAR X3 Pro 接入、调试与后续工作

本文对应原装 CP210x USB 转接板连接的 YDLIDAR X3 Pro。ROS 2 驱动配置位于
`src/spore_patrol_lidar`，自动检查程序位于 `tests/lidar`。

## 目前的配置基线

| 项目        |         当前值 | 说明                                        |
| ----------- | -------------: | ------------------------------------------- |
| 串口        | `/dev/ydlidar` | 未安装 udev 规则时使用 `/dev/ttyUSB0`       |
| USB 标识    |    `10c4:ea60` | Silicon Labs CP210x                         |
| 波特率      |         115200 | X3 系列官方配置                             |
| 单通道      |         `true` | X3 系列官方配置                             |
| 采样率参数  |          3 kHz | 驱动协议参数，不等于每秒输出圈数            |
| 扫描频率    |           5 Hz | 首轮联调的保守初值，以实测 `/scan` 为准     |
| 角度范围    |    -180°～180° | 完整 360°                                   |
| 距离范围    |    0.12～8.0 m | 按当前产品信息设置                          |
| 坐标系      |   `laser_link` | ROS 约定：前方 +x、左方 +y、上方 +z         |
| `reversion` |         `true` | 实物左前纸箱测试确定                         |
| `inverted`  |         `true` | 实物左前纸箱测试确定                         |

当前 URDF 暂定雷达在车体左右中线上、车体中心前方 100 mm，扫描平面离地约
350 mm。这个位置适合先做软件联调，不是最终安装尺寸。北斗天线、采样机构和外壳
位置确定后，应重新测量 `laser_joint` 的前后、左右、高度和偏航角。

## 第一次安装与编译

只需在首次拉取仓库或依赖版本改变后执行：

```bash
cd ~/spore_patrol_ws
source /opt/ros/humble/setup.bash
tools/setup_ydlidar_dependencies.sh
source tools/ydlidar_env.sh
colcon build --symlink-install
source install/setup.bash
```

脚本会按 `dependencies/ydlidar.repos` 中锁定的提交拉取 YDLidar-SDK 和 ROS 2
驱动。SDK 安装到 `.vendor`，驱动源码放到 `src/ydlidar_ros2_driver`；两者都由
Git 忽略，组员不需要把第三方源码提交进本仓库。

以后新开终端，运行雷达前都要执行：

```bash
source /opt/ros/humble/setup.bash
source tools/ydlidar_env.sh
source install/setup.bash
```

## 真雷达首次调试

### 1. 确认 USB 和权限

插入雷达，先不要启动 ROS：

```bash
python3 tests/lidar/lidar_test.py ports
groups
```

预期看到 CP210x、`10c4:ea60` 和 `/dev/ttyUSB0`。当前用户应属于 `dialout`
组。若不属于：

```bash
sudo usermod -aG dialout "$USER"
```

然后注销并重新登录。仅新开终端通常不会让已有桌面会话获得新组权限。

为了避免底盘和雷达插拔后设备号互换，推荐建立稳定名称：

```bash
tools/install_lidar_udev_rule.sh /dev/ttyUSB0
```

该脚本只会在转接板能提供唯一序列号时创建 `/dev/ydlidar`，不会用一个过宽的
规则误匹配其他 CP210x 设备。重新插拔后再次运行 `ports` 检查。

### 2. 单独启动雷达和 RViz

先让底盘保持静止，只启动雷达：

```bash
ros2 launch spore_patrol_lidar lidar_view.launch.py \
  port:=/dev/ttyUSB0
```

建立 `/dev/ydlidar` 后可以省略 `port`。RViz 中应看到车体模型和围绕雷达的
二维扫描点。另开终端检查：

```bash
source /opt/ros/humble/setup.bash
source tools/ydlidar_env.sh
source install/setup.bash
ros2 topic list -t
ros2 topic hz /scan
ros2 topic echo /scan --once
python3 tests/lidar/lidar_test.py scan --duration 30
```

自动测试会记录频率、每圈点数、角分辨率、有效点比例、观测距离和 `frame_id`，
结果保存在 `tests/results/时间_lidar_scan/summary.json`。

首次 30 秒测试的最低验收条件：

- 能连续收到 `/scan`，期间无串口断开和自动重连；
- `frame_id` 为 `laser_link`；
- 接收频率在 3～12 Hz 的合理范围内，并记录实际稳定值；
- 每圈点数在 300～1200 之间且没有大幅跳变；
- 房间内放置物体后，RViz 中对应位置能出现稳定轮廓。

3 kHz/4 kHz、宣传扫描频率和固件实际值的差异会影响每圈点数、角分辨率及建图
数据密度，但不会改变 ROS 接入方法。先用上面的程序记录真实结果；若频率长期不在
产品范围、点数明显异常或驱动反复报健康检查失败，再向客服确认确切硬件批次和固件
参数，不需要因宣传页的数字差异暂停当前开发。

### 3. 判断 `reversion` 和 `inverted`

这两个参数不是“接口朝哪边”的同义词：

- `reversion`：把整幅扫描旋转 180°，用于修正雷达正面装反；
- `inverted`：翻转角度递增方向，用于修正顺/逆时针定义导致的左右镜像。

把一个纸箱只放在小车左前方。ROS 坐标中它必须出现在 `x > 0、y > 0` 的左前象限。

```bash
python3 tests/lidar/lidar_test.py orientation
```

- 左前跑到右后：把 `reversion` 切换一次；
- 左前跑到右前：把 `inverted` 切换一次；
- 左前跑到左后：同时切换 `reversion` 和 `inverted`；
- 象限正确但整体总偏同一个角度：两个布尔量不再改，测量并修正 URDF 中
  `laser_joint` 的 yaw。

可先用启动参数试验，不必反复改文件：

```bash
ros2 launch spore_patrol_lidar lidar_view.launch.py \
  port:=/dev/ttyUSB0 \
  reversion:=true \
  inverted:=true
```

当前安装已经完成左前纸箱标定，最终值已写入
`src/spore_patrol_lidar/config/x3_pro.yaml`。

### 4. 与底盘一起启动

雷达单独测试通过后再合并：

```bash
ros2 launch spore_patrol_bringup hardware.launch.py \
  port:=/dev/ttyACM0 \
  lidar:=true \
  lidar_port:=/dev/ydlidar \
  rviz:=true
```

低速运动前检查：

```bash
ros2 topic hz /odom
ros2 topic hz /scan
ros2 run tf2_ros tf2_echo base_link laser_link
ros2 run tf2_ros tf2_echo odom laser_link
```

前一条 TF 是固定安装外参，后一条会同时验证底盘里程计和整棵 TF 是否连通。

## 常见故障

| 现象                                       | 优先检查                                                                |
| ------------------------------------------ | ----------------------------------------------------------------------- |
| 没有 `/dev/ttyUSB0`                        | 换可传数据的 USB 线/接口，运行 `lsusb`，确认 CP210x 是否出现            |
| `Permission denied`                        | `groups` 是否含 `dialout`；修改组后是否已经注销重登                     |
| `Cannot bind to the specified serial port` | 设备名是否正确；是否有另一个驱动占用；运行 `lsof /dev/ttyUSB0`          |
| 雷达在转但没有 `/scan`                     | 是否接在转接板 DATA 口；波特率是否 115200；终端是否加载了 ROS 环境      |
| `/scan` 有时中断                           | USB 插头、线缆应力、供电稳定性；查看驱动是否在自动重连                  |
| RViz 显示 `No transform`                   | 是否同时启动了 robot state publisher；Fixed Frame 是否可达 `laser_link` |
| 障碍物左右颠倒或前后颠倒                   | 用左前纸箱测试确定 `inverted`、`reversion`，不要凭雷达旋转方向猜        |
| 室外有效点骤降                             | 分别记录阴影和阳光直射；清洁窗口；检查深色叶片、细杆和远距离目标        |
| `/dev/ydlidar` 不出现                      | 转接板可能没有唯一序列号；暂用 `/dev/ttyUSB0`，不要写宽泛 VID/PID 规则  |

雷达“插入后能转”只能说明电机获得供电，不能证明串口通信、测距数据和坐标方向正确。

## 后续工作的顺序和验收记录

1. **台架静态测试**：室内连续运行 10 分钟，保存一次 30 秒摘要和驱动日志；在
   1 m、3 m、5 m、接近 8 m 处放置宽纸箱，核对距离。
2. **方向与外参**：完成左前纸箱测试；确定最终支架后，用卷尺记录
   `x/y/z/yaw`，更新 URDF 并复查 TF。
3. **线缆和供电**：固定 USB 线并做应力释放；雷达由电脑 USB 供电通信即可，但
   外场使用 USB 集线器时必须验证其供电和抗松动能力。
4. **底盘低速联调**：以 0.05 m/s、0.10 m/s 直行和原地缓慢旋转，观察扫描轮廓
   是否跳动、USB 是否断开，同时保存 `/scan` 与 `/odom`。
5. **室内建图**：接入 `slam_toolbox`，先做闭环房间地图；检查墙面重合、回环和
   停车后的地图漂移。
6. **室外数据评估**：分别测试阴天、树荫、阳光直射、作物叶片、细杆和不同地面，
   统计有效点比例与最远稳定距离。产品宣称的最大距离不能直接当作田间可靠距离。
7. **定位与导航**：雷达数据稳定后再加入轮速、IMU、北斗 RTK 融合和 Nav2，
   最后实现田间往复式覆盖路径以及“到点—停车—采样—确认—继续”状态机。

每个阶段保留：设备型号/序列号、安装照片、配置文件提交号、测试命令、
`summary.json`、现场环境和结论。这样调参失败时才能区分是硬件、安装、驱动还是算法问题。

## 已完成的软件验证

在未连接实物雷达时，已用 Gazebo 验证完整 `/scan` 测试链路：

- 10 秒收到 50 帧；
- 接收频率 4.964 Hz；
- 每圈 600 点，角分辨率约 0.601°；
- `frame_id=laser_link`；
- 自动检查通过。

这只证明配置、话题、TF 和测试工具可以工作，不替代上述真雷达验收。
