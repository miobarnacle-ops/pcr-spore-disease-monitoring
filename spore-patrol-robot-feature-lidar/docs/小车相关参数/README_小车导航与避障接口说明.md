# DG-202605 小车导航与避障接口说明

## 1. 文档目的

本文档用于说明“基于机器人与 DNA-PCR 技术的孢子病害识别关键技术研究”项目中，小车导航与避障模块的车辆运动约束、路径数据接口、坐标转换方法、任务执行策略、异常处理机制及跨小组数据需求。

本模块接收图像规划程序生成的采样点、巡检顺序及 `travel_waypoints_m` 航点序列，将离线全局路径转换为 R680 四驱移动机器人能够实际跟踪的 ROS 导航任务，并在执行过程中完成定位融合、速度控制、局部避障、到点采样和异常恢复。

本文档中的厂家参数来自当前 R680 高配版资料；加速度、减速度、定位精度阈值等未由厂家明确给出的参数，均作为初始工程设计值，最终应以负载状态下的实车试验结果为准。

---

## 2. 系统边界与总体流程

### 2.1 模块输入

导航与避障模块接收以下数据：

1. 图像规划模块输出的田块边界、采样点、访问顺序及全局航点序列；
2. RTK/北斗输出的全局位置；
3. IMU 输出的航向角、角速度和姿态；
4. 轮式编码器输出的里程计信息；
5. 激光雷达输出的障碍物和局部环境信息；
6. 采样模块输出的就绪、采样完成、失败及超时状态；
7. 底盘输出的电量、驱动状态及故障信息。

### 2.2 模块输出

导航与避障模块输出以下数据：

1. 底盘线速度和角速度控制指令；
2. 当前机器人位姿、任务状态和目标采样点；
3. 局部避障或重新规划后的执行路径；
4. 航点到达、采样触发、任务完成及异常告警信号；
5. 实际轨迹、横向误差、定位状态和避障事件日志。

### 2.3 执行流程

```text
系统初始化
  → 传感器与底盘自检
  → 加载地图、坐标配置和 JSON 路线
  → 校验路径版本、坐标系及航点合法性
  → 将局部田块坐标转换到 ROS map 坐标系
  → 导航至首个采样点
  → 到点减速并精确停靠
  → 等待车体稳定
  → 触发采样装置
  → 接收采样完成信号
  → 导航至下一采样点
  → 完成全部任务
  → 返回起点或指定停靠点
```

## 4. 车辆运动约束

### 4.1 通道宽度与安全余量约束

机器人车宽为：

```text
W_robot = 0.385 m
```

规则垄间通道的单侧基础几何安全距离暂取：

```text
d_geom = 0.30 m
```

暂不计定位与跟踪误差时，最小通行宽度为：

```text
W_required_geom
  = W_robot + 2 × d_geom
  = 0.385 + 2 × 0.30
  = 0.985 m
```

设计最小通道宽度为：

```text
W_channel = 1.20 m
```

机器人位于通道中心时，单侧总可用空间为：

```text
d_available
  = (W_channel - W_robot) / 2
  = (1.20 - 0.385) / 2
  = 0.4075 m
```

扣除 0.30 m 基础几何安全距离后，单侧仅剩：

```text
d_error_budget = 0.4075 - 0.30 = 0.1075 m
```

因此，“1.20 m 通道满足安全通行要求”的成立条件为：机器人横向定位误差、轨迹跟踪误差及地图误差的综合影响应控制在约 0.10 m 以内。比赛规定的“定位误差小于 0.5 m”是总体性能下限，不能作为垄间正常行驶时允许的横向偏差。

建议工程目标如下：

- 横向轨迹误差 RMSE 不大于 0.10 m；
- 95% 横向轨迹误差不大于 0.20 m；
- 横向偏差超过 0.20 m 时降速纠偏；
- 横向偏差超过 0.30 m 时停车，执行重新定位或局部重规划；
- 系统总体定位误差满足比赛规定的小于 0.5 m。

路径中心线应位于膨胀后的可通行区域内，并尽量靠近通道中线，避免车体、车轮及安装装置侵入作物区域。

### 4.2 车体碰撞模型与障碍物膨胀

采样装置不超过车体外轮廓时，机器人碰撞模型采用矩形：

```text
长度 = 0.465 m
宽度 = 0.385 m
```

ROS 局部代价地图中应优先使用实际矩形轮廓，不应只把机器人简化为质点。规划前应对作物区域、静态障碍物和田块边界进行安全膨胀。

推荐按环境类型设置膨胀距离：

| 场景 | 建议基础膨胀距离 |
|---|---:|
| 规则垄间通道 | 0.30 m |
| 地头及田块边界 | 0.40～0.50 m |
| 固定硬质障碍物 | 0.40～0.50 m |
| 人员、农机等动态障碍物 | 不小于 0.50 m |

在 1.20 m 通道中不能统一采用 0.50 m 单侧膨胀，否则所需宽度为：

```text
0.385 + 2 × 0.50 = 1.385 m > 1.20 m
```

因此，0.50 m 膨胀仅适用于更宽的地头、开放区域或高风险障碍物周围。最终安全边界还应结合定位误差、跟踪误差和地图误差进行校核。

若采样装置后续伸出车体，则碰撞模型必须按照安装后的最大外轮廓重新建立，不得继续使用原车体尺寸。

### 4.3 速度约束

底盘最大速度为：

```text
v_max = 1.82 m/s
```

巡检规划速度为：

```text
v_plan = 0.50 m/s < v_max
```

建议分场景限速：

| 场景 | 建议速度 |
|---|---:|
| 垄间直线巡检 | 0.40～0.60 m/s |
| 接近采样点 | 0.10～0.20 m/s |
| 转弯或地头掉头 | 0.10～0.30 m/s |
| 局部环境不确定 | 不大于 0.20 m/s |
| 开放且确认安全的地头区域 | 不大于 0.80 m/s |

田间任务不建议使用 1.82 m/s 的底盘极限速度。局部规划器应根据障碍物距离、路径曲率、定位质量和地面条件动态降低速度。

### 4.4 加减速度与停车距离约束

厂家资料未给出底盘在负载状态下的加速度、减速度和控制延迟。初始调试阶段建议采用以下保守值：

| 参数 | 初始工程值 |
|---|---:|
| 最大线加速度 | 0.30～0.50 m/s² |
| 最大线减速度 | 0.50～0.80 m/s² |
| 最大角加速度 | 0.50～1.00 rad/s² |

安全停车距离按下式计算：

```text
d_stop = v × t_delay + v² / (2 × a_brake) + d_margin
```

其中：

- `v` 为当前线速度；
- `t_delay` 为感知、规划、通信和底盘响应的总延迟；
- `a_brake` 为实测安全减速度；
- `d_margin` 为附加安全距离。

上述参数必须通过携带实际采样装置的实车制动试验进行标定。激光雷达减速区和停车区的设置不得小于实测最不利停车距离。

### 4.5 差速转向与曲率约束

R680 采用四轮差速/滑移转向。左右侧轮速关系为：

```text
v_left  = v × (R - B/2) / R
v_right = v × (R + B/2) / R
```

其中：

- `v` 为车体中心线速度；
- `R` 为车体中心转弯半径；
- `B = 0.3356 m` 为轮距。

为减少田间松软地面上的侧向滑移、地表扰动和定位误差，正常巡检不采用高速原地急转，初始工程最小转弯半径取：

```text
R_min = 0.50 m
```

当 `R = 0.50 m` 时：

```text
v_left / v_right
  = (0.50 - 0.3356/2) / (0.50 + 0.3356/2)
  ≈ 0.50
```

当 `v = 0.50 m/s`、`R = 0.50 m` 时：

```text
omega = v / R = 1.00 rad/s
```

初始路径执行约束为：

```text
R_turn ≥ 0.50 m
|omega| ≤ 1.00 rad/s
```

`travel_waypoints_m` 输出的折线需要在下发到底盘前进行圆弧、Bezier 曲线或样条平滑。平滑后仍应使用完整矩形车体轮廓进行碰撞检测，防止车头或车尾在转弯时扫入作物区域。

原地转向仅用于宽阔地头、任务恢复或低速精确调整，不作为垄间常规转向方式。

### 4.6 越障与坡度约束

底盘标称单级直角台阶越障高度为：

```text
H_max = 55 mm
```

该值属于产品上限，并会受到负载、障碍物形状、接近角度、轮胎附着力和土壤松软程度影响。工程设计建议：

- 已知、规则且高度不超过 35～45 mm 的障碍物，可在试验验证后低速通过；
- 高度接近 55 mm 的障碍物不作为常规通行条件；
- 未分类障碍物默认减速、停车或绕行；
- 超过实测安全越障高度的障碍物必须重新规划。

二维激光雷达通常无法可靠测量低矮障碍物高度。若系统需要自动区分可跨越台阶、坑洼及沟渠，应增加深度相机、三维激光雷达或其他地形感知装置。

底盘标称最大爬坡角为：

```text
theta_max = 25°
```

考虑湿滑土壤、负载和侧滑风险，建议工程安全坡度控制在 15°～20°。接近安全上限时应降低速度，超过实测安全坡度时应绕行。横坡场景还需单独测试侧倾稳定性，不能仅使用最大纵向爬坡角作为依据。

### 4.7 定位、航点到达与偏航约束

定位系统采用 RTK/北斗、IMU、轮式编码器和激光雷达融合：

- RTK/北斗提供全局位置基准；
- IMU 提供航向角、角速度、俯仰角和短时运动补偿；
- 轮式编码器提供连续里程计；
- 激光雷达提供局部环境匹配和障碍物检测。

机器人按照 `travel_waypoints_m` 形成的路径逐段跟踪。必须区分“航点到达误差”和“横向轨迹偏差”。

航点到达误差定义为：

```text
e_goal = distance(P_robot, P_target)
```

当满足以下条件时，可认为到达普通过渡航点：

```text
e_goal ≤ 0.20 m
```

采样点应同时满足位置、速度和姿态稳定条件，例如：

```text
e_goal ≤ 0.20 m
|v| ≤ 0.05 m/s
|omega| ≤ 0.10 rad/s
并持续稳定 1～2 s
```

横向轨迹偏差定义为机器人当前位置到当前路径段的最短距离：

```text
e_ct = min distance(P_robot, Q), Q ∈ current_path
```

建议执行规则：

| 条件 | 处理策略 |
|---|---|
| `e_ct ≤ 0.20 m` | 正常跟踪 |
| `0.20 m < e_ct ≤ 0.30 m` | 降速并纠偏 |
| `e_ct > 0.30 m` | 停车，重新定位或局部重规划 |
| 定位失效或协方差超限 | 停车并告警 |

不能使用“机器人到下一个航点的距离大于 0.5 m”判断偏航，因为机器人在正常前往远距离航点时，该距离本来就可能远大于 0.5 m。

比赛要求的定位误差小于 0.5 m应通过实测轨迹与高精度参考轨迹对比进行验证，并给出 RMSE、最大误差或 95% 分位误差，不直接作为航点距离故障判据。

### 4.8 能量与负载约束

单次任务执行前应根据路径长度、规划速度、采样次数和单点采样时间估算总任务时间：

```text
T_mission
  = T_navigation
  + T_sampling
  + T_avoidance
  + T_recovery
  + T_return
```

续航校核必须以安装实际采样装置后的实测结果为准。建议预留不低于 25%～30% 的返航及异常处理电量。若底盘能够提供可靠的电量状态，则低于设定阈值时停止接受新的采样任务并执行返航。

## 5. 坐标系与路径转换

### 5.1 坐标处理原则

不建议把 JSON 中的每个局部航点直接改写为经纬度。导航规划和轨迹跟踪应保留以米为单位的局部直角坐标，并建立以下转换链：

```text
图像像素坐标 (u, v)
  → 田块局部 ENU 坐标 (x, y)
  → ROS map 坐标系
  → odom 坐标系
  → base_link 车体坐标系
```

RTK/北斗输出的经纬度应依据已测定的田块原点转换为局部 ENU 坐标，再与 JSON 路径进行匹配。

### 5.2 必需的坐标配置

路径文件或配套配置文件至少应包含：

```json
{
  "coordinate_system": {
    "frame_id": "map",
    "type": "local_enu",
    "unit": "m",
    "origin": {
      "latitude_deg": null,
      "longitude_deg": null,
      "altitude_m": null
    },
    "x_axis_heading_deg": null,
    "crs": "WGS84_or_CGCS2000",
    "map_resolution_m": null
  }
}
```

其中 `null` 字段必须由定位或建图小组通过现场测量补充。坐标原点、X 轴方向和地理坐标基准一旦确定，同一地块内的地图、路径和实测轨迹必须使用同一版本。

### 5.3 JSON 路径数据要求

现有路径文件中的核心字段为：

- `sampling_points`：采样点列表；
- `path_rounds`：巡检轮次；
- `tour_order`：采样点访问顺序；
- `segments`：分段路径；
- `travel_waypoints_m`：局部米制航点序列。

建议补充以下元数据：

```json
{
  "meta": {
    "schema_version": "5.0",
    "map_id": "field_001",
    "route_id": "route_001",
    "created_at": "YYYY-MM-DDTHH:MM:SS+08:00",
    "frame_id": "map",
    "unit": "m",
    "vehicle_model": "R680_4WD",
    "route_type": "closed_or_open"
  },
  "mission": {
    "start_pose": {
      "x_m": 0.0,
      "y_m": 0.0,
      "yaw_rad": 0.0
    },
    "return_pose": {
      "x_m": 0.0,
      "y_m": 0.0,
      "yaw_rad": 0.0
    }
  }
}
```

每个航点建议统一为对象形式，以便携带速度和任务属性：

```json
{
  "id": "WP-001",
  "x_m": 0.0,
  "y_m": 0.0,
  "yaw_rad": null,
  "speed_limit_ms": 0.5,
  "type": "transit",
  "tolerance_m": 0.2
}
```

`type` 可取：

- `start`：任务起点；
- `transit`：普通过渡航点；
- `sampling`：采样点；
- `turn`：转弯或掉头控制点；
- `return`：返航点。

为兼容现有文件，程序可继续读取 `[x, y]` 数组形式的 `travel_waypoints_m`，并在加载后转换为内部标准航点对象。

### 5.4 路径加载校验

路径下发前至少执行以下检查：

1. JSON 格式及版本是否正确；
2. 坐标单位是否为米；
3. `frame_id` 是否与当前地图一致；
4. 地图版本和路径版本是否匹配；
5. 航点是否位于田块边界内；
6. 航点和线段是否进入膨胀后的作物或障碍物区域；
7. 相邻航点是否连续；
8. 平滑后的曲率是否满足 `R_turn ≥ 0.50 m`；
9. 起点、返航点和采样点是否完整；
10. 预计任务时间和电量是否满足要求。

任一关键检查失败时不得直接启动自动巡检。

## 6. 导航、避障与任务执行策略

### 6.1 分层规划

系统采用分层规划结构：

1. 图像规划层：识别田块、作物垄和可通行区域，生成采样点与全局访问顺序；
2. 全局导航层：将 `travel_waypoints_m` 转换为连续、无碰撞且满足曲率约束的全局路径；
3. 局部规划层：根据实时激光雷达数据对人员、农机和临时障碍物进行减速、停车或绕行；
4. 轨迹控制层：输出底盘线速度与角速度，完成路径跟踪；
5. 任务管理层：协调导航、采样、返航和异常恢复。

对于四轮差速底盘，可优先采用以下 ROS 方案：

- 全局规划：A* 或 Smac Planner 2D；
- 局部规划：DWB、TEB 或 MPPI；
- 路径跟踪：Regulated Pure Pursuit；
- 安全停车：Collision Monitor；
- 状态估计：RTK/北斗、IMU、轮式里程计和激光定位融合。

具体软件组件可根据已购买 ROS 套餐和主控算力调整。

### 6.2 到点采样状态机

建议任务状态定义如下：

| 状态 | 含义 |
|---|---|
| `INIT` | 系统初始化与自检 |
| `LOAD_ROUTE` | 加载并校验路径 |
| `NAVIGATING` | 前往当前目标点 |
| `APPROACHING` | 接近采样点并降速 |
| `STABILIZING` | 停车并等待车体稳定 |
| `SAMPLING` | 触发采样装置 |
| `WAITING_ACK` | 等待采样完成或失败响应 |
| `NEXT_POINT` | 切换至下一目标点 |
| `REPLANNING` | 局部或全局重规划 |
| `RETURNING` | 返航 |
| `COMPLETED` | 任务完成 |
| `FAULT` | 故障停车并告警 |

采样模块必须返回明确的完成、失败和超时状态。导航模块不得仅按固定延时假定采样已经完成。

### 6.3 障碍物处理

建议采用分级策略：

1. 障碍物进入减速区：降低线速度；
2. 障碍物进入停车区：立即停止；
3. 障碍物短时存在：等待并持续检测；
4. 存在可行绕行空间：执行局部重规划；
5. 当前通道完全阻塞：执行全局重规划；
6. 无可行路径：跳过当前任务点或请求人工接管，并保存告警记录；
7. 人员进入安全区域：优先停车，不执行贴近绕行。

### 6.4 定位异常处理

出现以下任一情况时，应降低速度或停车：

- RTK 固定解丢失；
- 定位协方差超过阈值；
- 激光定位与 RTK 位置差异持续超限；
- IMU 航向突变；
- 里程计与外部定位长期不一致；
- 横向轨迹偏差超过 0.30 m；
- 传感器数据超时或时间不同步。

短时间 RTK 失锁时，可依靠 IMU、编码器和激光定位维持低速运行；若定位质量在设定时间内未恢复，应停车并告警，不得继续盲目跟踪全局路径。

### 6.5 孢子浓度闭环

孢子浓度和 PCR 结果不直接参与底层避障，但可以用于高层任务更新：

1. 到达采样点并完成采样；
2. 采样模块返回浓度或风险等级；
3. 若浓度超过阈值，在高风险区域周围生成复检点；
4. 校验新增点的可达性和剩余电量；
5. 更新任务队列并重新规划访问顺序；
6. 保存原始任务、更新原因和新路线版本。

该闭环可作为“机器人巡检与病害检测融合”的系统创新点，但具体浓度阈值应由孢子检测或 PCR 小组确定。

## 7. 跨小组数据接口

### 7.1 全局路径规划组需提供

- JSON Schema 或字段说明；
- `travel_waypoints_m` 的坐标系、原点、方向和单位；
- 田块边界、作物区域及静态障碍物区域；

- 路径生成算法版本；
- 地图和路径版本号；
- 推荐速度或特殊航点类型；
- 路径更新和重新下发机制。

### 7.2 定位与建图组需提供

- RTK 基站或田块局部坐标原点；
- 原点经纬度、高程和坐标基准；
- 局部 ENU 坐标系 X 轴方向；
- 激光雷达地图或占据栅格地图；
- 地图分辨率、原点、方向和版本；
- ROS TF 坐标关系；
- RTK、IMU、里程计、雷达消息格式和话题名称；
- 定位结果、协方差及状态质量标志；
- 传感器外参和时间同步方案。

### 7.3 采样与 PCR 组需提供

- 采样装置最大外形尺寸；
- 装置质量、安装位置和重心变化；
- 是否存在伸出车体的运动机构；
- 到点后允许的位置和姿态误差；
- 停车稳定时间；
- 采样启动、完成、失败和超时接口；
- 单次采样预计时间；
- 采样过程中是否允许车体移动；
- 孢子浓度、风险等级及 PCR 结果的数据格式；
- 高浓度触发复检的判定阈值。

### 7.4 底盘与 ROS 集成需确认

- 实际购买套餐包含的主控、雷达、IMU 和驱动器；
- 底盘速度控制接口及 `cmd_vel` 支持情况；
- 编码器和里程计数据频率；
- 急停、遥控接管及故障码接口；
- 电池电量读取方式；
- 最大线加速度、减速度和角速度的实测值；
- 携带采样装置后的续航、制动和转向性能。

## 10. 当前假设与待确认事项

### 10.1 当前采用的设计假设

- 底盘为 R680 四驱移动机器人高配版；
- 采样装置不超过车体外轮廓；
- 最小通道宽度为 1.20 m；
- 垄间基础几何安全距离为单侧 0.30 m；
- 巡检规划速度为 0.50 m/s；
- 最小工程转弯半径为 0.50 m；
- 最大建议角速度为 1.00 rad/s；
- 普通航点到达容差为 0.20 m；
- 横向偏差超过 0.30 m时停车纠偏或重规划；
- 定位采用 RTK/北斗、IMU、编码器和激光雷达融合；
- JSON 中 `travel_waypoints_m` 为局部米制坐标。

### 10.2 必须通过实车或跨组沟通确认

- 采样装置最终尺寸、质量、重心和工作方式；
- RTK 坐标原点及局部 ENU 坐标定义；
- 激光地图格式、分辨率和版本；
- ROS 套餐实际硬件和软件组件；
- 满载加速度、减速度、制动距离和侧滑特性；
- 1.20 m通道内能否达到约0.10 m的横向综合误差；
- 负载状态下的安全越障高度和坡度；
- 采样触发、完成、失败和超时接口；
- 孢子浓度异常后的复检策略；
- 电池状态读取与自动返航阈值。

在上述事项完成确认前，相关数值只作为方案设计和仿真初值，不应表述为已经通过实车验证的最终性能指标。
