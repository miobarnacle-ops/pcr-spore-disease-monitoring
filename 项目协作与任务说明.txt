================================================

一、项目和仓库
--------------

项目目标：
在现有WHEELTEC C50X四驱底盘和STM32下位机基础上，完成机器人定位建图、
路径规划、避障、任务点停车和采样模块协同。

GitHub仓库：
https://github.com/BrownSun250912/spore-patrol-robot

仓库目前为公开仓库。没有GitHub账号也可以查看代码、下载ZIP、git clone和
git pull；但是如果要git push、创建Pull Request、领取Issue或者提交代码，
仍然必须注册GitHub账号。

希望三位组员尽快注册免费GitHub账号，并把用户名发给组长，由组长添加为
Collaborator。没有账号只能临时下载和测试，不能形成规范的GitHub协作记录。


二、第一次下载项目
------------------

Ubuntu终端执行：

git clone https://github.com/BrownSun250912/spore-patrol-robot.git
cd spore-patrol-robot

配置自己的提交身份：

git config user.name "自己的GitHub用户名或姓名"
git config user.email "自己的GitHub邮箱"

编译项目：

source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash

启动Gazebo演示：

ros2 launch spore_patrol_bringup demo.launch.py

只启动RViz机器人模型：

ros2 launch spore_patrol_description display.launch.py

第一次任务：
每个人必须独立完成克隆、编译和启动，并把成功截图或错误日志发到群里。
不要只回复“环境装好了”或者“正在学习”。

四、正式GitHub协作流程
--------------------

重要原则：
每个人只在自己的功能分支开发，不直接修改或推送main。

1. 开始任务前同步main

git switch main
git pull --ff-only origin main

2. 从最新main创建自己的分支

雷达负责人：
git switch -c feature/lidar

北斗负责人：
git switch -c feature/gnss

硬件负责人：
git switch -c feature/chassis-hardware

如果分支已经存在，不要重复创建，使用：

git switch feature/lidar

3. 修改前查看状态

git status

4. 完成一小项任务后提交

不要无脑git add .，优先只添加自己修改的文件，例如：

git add src/spore_patrol_lidar
git add docs/lidar_selection.md

提交：

git commit -m "feat(lidar): add lidar selection and launch"

5. 推送自己的分支

第一次：

git push -u origin feature/lidar

以后：

git push

6. 在GitHub创建Pull Request

base选择main；
compare选择自己的feature分支；
写清做了什么、怎么运行、如何测试、目前有什么问题；
附上截图、日志或视频；
提交后通知组长检查；
未经检查不要自行合并。


五、开发中如何同步别人已经合并的代码
----------------------------------

先提交或保存自己的修改，然后：

git fetch origin
git switch 自己的功能分支
git merge origin/main

出现冲突时不要删除别人的文件，也不要使用强制推送。把冲突文件和终端信息
发给组长，一起解决。

不建议初学阶段使用：

git push --force
git reset --hard
git rebase


六、Pull Request合并之后
-----------------------

更新本地main：

git switch main
git pull --ff-only origin main

确认功能分支已经合并后，可以删除本地旧分支：

git branch -d feature/lidar

下一项工作从最新main重新建立分支，不要在已经合并的旧分支无限追加任务。


七、没有GitHub账号时的临时办法
----------------------------

没有账号可以执行：

git clone https://github.com/BrownSun250912/spore-patrol-robot.git
cd spore-patrol-robot
git pull --ff-only origin main

也可以下载ZIP、编译、运行和填写测试记录。

临时情况下可以把修改文件、测试记录和日志交给组长，由组长代为检查和提交。
这只作为过渡方案。长期协作必须注册GitHub账号。

九、公开仓库安全要求
------------------

当前仓库任何人都能看到，因此禁止上传：
- GitHub Token、密码、SSH私钥和账号凭据；
- Wi-Fi密码、CORS/NTRIP账号密码和SIM卡信息；
- 个人身份证、手机号、家庭地址等隐私；

- 来源不清楚、没有授权公开的代码。

发现密钥或密码已经提交时，不要只删除文件，必须立即通知组长并更换凭据。


十、共同目标
------------

当前第一阶段不是立刻实现完整自主导航，而是分别打通：

底盘：
电脑命令 -> STM32 -> 四轮运动 -> 编码器/IMU反馈 -> 失联停车

雷达：
雷达 -> ROS 2 /scan -> RViz -> SLAM地图

北斗：
RTK接收机 -> NMEA/RTCM -> /gps/fix和航向 -> RTK Fix

三条链路分别通过后，再统一进行轮速、IMU、RTK和激光SLAM融合，最后接入
Nav2路径规划和孢子采样任务状态机。

有问题时请提交完整命令、完整报错、相关文件和截图，不要只说“运行不了”。
