# 《穗巡》多端展示应用 8 小时自动推进计划

- 基线：《穗巡》多端展示应用封装推进计划书 V1.0
- 执行窗口：约 8 小时
- 执行方式：连续自动开发、阶段性验证、遇到打包工具链阻塞时自动转入可继续任务
- 当前团队署名占位：`穗巡项目团队`（位于 `src/brand.ts`）

## 一、本轮目标

在 8 小时内形成一套可运行、可继续打包的多端展示应用工程，优先完成：

1. 选定 Logo 的工程化归档和透明素材处理。
2. PC 端展示应用的主界面、启动动画和 Electron 外壳。
3. Android 竖屏展示界面的主界面、启动动画和 Capacitor 工程结构。
4. 统一品牌配置、模拟数据和交互动效。
5. 本地构建、响应式检查、安全检查和交付文档。

本轮不会修改 `spore-monitor-web` 的现有工作区；新工作全部放在 `multiplatform-showcase` 中。

## 二、当前环境与产出边界

已确认本机具备：

- Node.js 24.15.0。
- npm 11.12.1。
- OpenJDK 21。

当前未发现：

- Android SDK、`sdkmanager`、`adb` 和系统 Gradle。
- Windows 交叉打包所需的 Wine/NSIS。

因此，本轮无条件保证交付的是两端完整源代码、可运行预览、Web 生产构建、Electron/Capacitor 打包配置、图标素材和测试报告。Windows EXE 与 Android APK 取决于对应工具链能否在执行窗口内完成安装和配置；若打包受阻，不等待、不停工，自动完成其余任务并留下单命令构建入口和明确阻塞说明。

## 三、8 小时任务时间表

### 00:00～00:30：基线冻结与工程初始化

- 创建 `shared`、`desktop`、`mobile`、`release`、`scripts` 和测试目录。
- 建立统一版本号、应用名称和团队署名配置。
- 记录现有 Web 控制台的设计令牌：背景色、强调色、风险色、圆角、阴影和字体层级。
- 固定离线展示模式，禁止导入真实 ROS 控制接口。
- 建立项目 README、构建命令和质量检查脚本。

阶段验收：工程结构清晰；所有应用名称都从单一配置读取；原 Web 仓库无新增改动。

### 00:30～01:15：Logo 与品牌素材工程化

- 归档当前选定的 Logo 概念图。
- 去除图片中可见棋盘格，生成真实透明背景版本。
- 保留原始概念图，不覆盖源文件。
- 生成方形图标、横排 Logo、深色背景预览及常用尺寸切片。
- 建立桌面和移动端共同使用的品牌资源清单。

阶段验收：透明边缘无明显白边；Logo 在 32px、64px、128px 和 512px 下可识别；“穗巡”文字清晰。

### 01:15～02:15：共享界面基础与启动动画

- 创建统一的颜色、字体、间距和动画变量。
- 实现 2.5～3.5 秒启动动画。
- 动画包含 Logo、应用名称、DNA 轨迹、扫描光和团队署名。
- 团队名称使用 `src/brand.ts` 单一占位配置，后续只需修改一处。
- 实现启动动画结束后主页面无白屏过渡。
- 支持“减少动态效果”系统设置，避免低性能设备卡顿。

阶段验收：桌面横屏和手机竖屏均能完整播放；重复启动行为一致；动画不依赖网络。

### 02:15～03:35：Windows 桌面端核心界面

- 建立 Electron + React 桌面端外壳。
- 复用现有控制台的深色农业科技设计语言，不直接复制真实控制代码。
- 完成顶部状态栏、侧边导航、巡检地图、风险卡片、环境数据、PCR 概览、机器人状态和告警列表。
- 使用固定模拟数据展示路线、采样点、电量和预警变化。
- 对所有可能被误认为真实控制的按钮增加演示模式隔离。
- 适配 1920×1080 与 1366×768。

阶段验收：桌面页面可以独立运行；导航和主要卡片可点击；控制台无错误；无 ROS、WebSocket 和后端请求。

### 03:35～04:40：桌面端细节与 Electron 集成

- 完成窗口图标、标题、最小尺寸、最大化和退出行为。
- 增加页面渐入、数字滚动、地图路线绘制和雷达扫描动效。
- 配置 Electron 安全选项：关闭 Node 页面注入、启用上下文隔离、限制外部导航。
- 配置 Windows 安装包元信息、桌面快捷方式和发行脚本。
- 尝试生成当前环境允许的桌面构建产物。

阶段验收：开发模式和生产渲染构建均可启动；无浏览器地址栏和终端依赖；打包配置完整。

### 04:40～06:00：Android 手机竖屏界面

- 建立 React/Vite + Capacitor 移动端工程。
- 完成首页、巡检、分析、我的四个一级页面。
- 使用底部导航、信息卡片和竖屏地图缩略图。
- 首页显示风险等级、任务进度、PCR 结果、机器人电量、温湿度和告警数量。
- 巡检页显示简化路线、采样点和当前位置。
- 分析页显示 PCR 判定、风险趋势及 3/5/7 天概览。
- 我的页面显示应用版本、项目简介和团队占位信息。

阶段验收：360～430px 宽度无横向溢出；触控区域足够；主要内容无需缩放即可阅读。

### 06:00～06:45：移动端动效与 Capacitor 集成

- 接入竖屏启动动画和应用图标。
- 添加卡片展开、页面切换、数字变化和风险状态动效。
- 处理状态栏、底部安全区和 Android 返回键逻辑。
- 配置 Capacitor 应用 ID、应用名称和 Android 项目生成脚本。
- 若 Android SDK 可用，则尝试生成调试 APK；否则完成全部构建准备。

阶段验收：手机浏览器预览正常；Capacitor 配置可解析；Android 项目生成步骤可复现。

### 06:45～07:30：统一测试和离线检查

- 执行 lint、TypeScript 类型检查和生产构建。
- 检查页面是否发起外部网络请求。
- 搜索并阻断 ROS、`cmd_vel`、SSH、密码和私密设备地址。
- 检查 Logo、字体、模拟数据和动画资源是否全部内置。
- 检查桌面端与手机端的关键分辨率。
- 检查团队名称替换是否只涉及 `src/brand.ts` 单一配置项。

阶段验收：生产构建通过；无敏感信息；无真实控制接口；离线模式可运行。

### 07:30～08:00：交付整理与状态报告

- 整理 `release` 目录和可用构建产物。
- 编写运行、构建、Windows 打包和 Android 打包说明。
- 输出已完成项、验证结果、剩余阻塞和下一步命令。
- 记录所有自动修改文件，保留原 Logo 概念图。
- 复核 `spore-monitor-web` 和其他原仓库未被误改。

阶段验收：任何接手者都能依据 README 启动两端应用；构建状态和未完成项没有歧义。

## 四、自动执行原则

- 不等待团队名称确认，统一使用 `穗巡项目团队` 占位，并保证后续一处替换。
- 不修改当前存在未提交工作的 `spore-monitor-web`。
- 不连接真实机器人、rosbridge、数据库或互联网服务。
- 不发送任何真实运动控制指令。
- 不读取或复制私密交接文档中的凭据。
- 不覆盖现有 Logo，所有处理结果采用版本化文件名。
- 某一打包工具链阻塞超过 15 分钟时，立即切换到界面、测试、文档或其他可完成任务。
- 每个阶段结束后执行最小验证，避免把错误积累到最后。

## 五、8 小时结束时的目标交付物

### 必达交付

- `multiplatform-showcase` 独立工程。
- 选定 Logo 原图与透明处理版本。
- Windows 桌面端可运行源码和生产前端构建。
- Android 竖屏端可运行源码和生产前端构建。
- 两端启动动画。
- 统一模拟数据、品牌配置和团队名称占位配置。
- Electron 与 Capacitor 打包配置。
- 自动检查脚本、构建说明和阶段报告。

### 条件交付

- Windows `.exe`：需要 Wine/NSIS 或 Windows 构建环境。
- Android `.apk`：需要 Android SDK、平台工具及对应构建平台。

若条件交付未能在当前主机生成，工程仍需达到在具备工具链的环境中通过单条命令继续打包的状态。
