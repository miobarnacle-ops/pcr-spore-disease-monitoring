# 《穗巡》多端展示应用审计与修订报告

审计日期：2026-09-06  
审计基线：《多端展示应用封装推进计划书 V1.0》与《穗巡 8 小时自动推进计划》

## 审计结论

本轮发现的功能一致性、安全边界和交付验证缺口均已修订。项目现已具备可用于介绍视频拍摄的 Windows 标准安装器、便携应用、Android 竖屏展示 APK、统一品牌过场和离线模拟界面。

## 已发现并修订

| 审计项 | 原问题 | 修订结果 |
| --- | --- | --- |
| 移动端信息架构 | 原页面偏向“预警/机器人”，缺少计划中的“分析/项目” | 调整为“首页/巡检/分析/项目”，补充 PCR 摘要、3/5/7 日趋势和项目说明 |
| Android 版本 | 原生 `versionName` 为 1.0，与应用 0.1.0 不一致 | 已统一为 0.1.0 |
| 减少动态效果 | CSS 可减少动画，但启动仍固定等待约 2.85 秒 | 启用系统减少动态效果时缩短至约 0.32 秒 |
| 离线边界 | 主要依赖实现约定 | 增加 CSP、Electron 网络/下载拦截，并移除 Android 网络权限 |
| 依赖安全 | Electron 旧版本触发 2 个 high severity 告警 | 升级至 Electron 44.2.0，审计结果为 0 vulnerabilities |
| 自动检查 | 仅检查资源和少量敏感词 | 增加版本、应用名、竖屏、权限、CSP、Electron 隔离和移动导航检查 |
| 交付检查 | 缺少统一包体检查命令 | 新增 `npm run check:release`，核对 EXE/APK 文件头、尺寸和核心运行资源 |
| 重复拍摄 | 原交互需要人工逐页操作且缺少统一复位 | 新增桌面五阶段、手机四阶段自动导览，支持停止、手动接管和重置 |
| 品牌口径 | 团队名称待定，OFFLINE 标识较突出 | 团队名确定为“穗巡项目团队”，主界面仅弱化显示“演示模式” |
| 桌面过场 Logo | portable 使用 `file://` 打开 `dist/index.html` 时，`/brand/...` 绝对路径指向系统根目录，Logo 无法显示 | 品牌图片改用 `./brand/...` 相对路径，重建标准安装器、portable 包和解包运行目录，并检查包内资源 |

## 验证结果

- `npm run check`：通过。
- `npm run audit:security`：通过，0 vulnerabilities。
- 浏览器功能验收：桌面 5 页与移动 4 页均可切换；3D/5D/7D 趋势切换正常。
- 响应式验收：360×800、393×873、412×915 均无横向溢出。
- 浏览器控制台：0 条错误。
- Windows：标准安装器、便携 EXE 与解包主程序均为有效 PE 文件，`app.asar` 完整。
- Windows 资源复验：标准安装器、便携 EXE 和解包运行目录中的 `app.asar` 均包含两份 Logo，构建脚本使用相对 `./brand/...` 路径。
- Android：APK 为有效 ZIP/APK，包名 `cn.suixun.showcase`，版本 0.1.0，标签“穗巡”，v1/v2 签名有效，不申请 INTERNET 权限。

## 保留事项

以下不影响本轮视频展示，仅在未来公开发布时需要：

1. 如对外分发，使用团队 release 密钥签署 Android 正式包，并为 Windows 购买代码签名证书。
2. 在最终拍摄设备上做一次真机启动与比例复核。
