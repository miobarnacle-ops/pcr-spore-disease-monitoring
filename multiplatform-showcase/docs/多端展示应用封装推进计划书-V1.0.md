# 《穗巡》多端展示应用封装推进计划书 V1.0

- 项目名称：穗巡
- 版本：V1.0
- 日期：2026-09-06
- 团队创始名称：穗巡项目团队
- 项目定位：Windows 与 Android 离线展示应用

## 一、项目目标

将现有孢子病害监测 Web 控制台封装为两个独立的展示应用：

| 端 | 交付形式 | 核心目标 |
|---|---|---|
| Windows PC 端 | 可双击安装的 `.exe` 安装包 | 延续现有 Web 控制台风格，呈现完整的大屏控制界面 |
| Android 移动端 | 可直接安装的 `.apk` | 针对手机竖屏重新设计精简界面，体现移动巡检和状态查看能力 |

两个应用均定位为“离线展示应用”，不连接真实机器人、PCR 设备或后端服务，但应具备完整视觉效果、模拟数据和基本点击反馈。

## 二、范围界定

本阶段包含：

- Windows 安装包和 Android APK。
- 应用图标、启动图、名称、版本信息和团队署名。
- 丝滑的启动过场动画。
- 现有 Web 控制台视觉风格的复用。
- 手机竖屏专用界面。
- 内置静态数据和模拟状态。
- 页面切换、按钮反馈、图表变化等轻量交互。
- 完全离线运行，不依赖服务器和网络。
- 安装、启动和卸载验证。

本阶段不包含：

- 真实机器人远程控制。
- ROS/rosbridge 实时通信。
- 真实 PCR 数据接入。
- 用户登录和权限系统。
- 云端数据库、消息推送或应用商店上架。
- Windows、Android 之外的平台适配。

## 三、总体技术方案

独立建立多端展示工程，避免影响正在开发且存在未提交修改的 `spore-monitor-web`：

```text
multiplatform-showcase/
├── shared/           # 品牌配置、颜色、字体、图标、模拟数据
├── desktop/          # Windows 桌面端
├── mobile/           # Android 移动端
├── assets/           # Logo、启动画面、背景、应用图标
├── release/          # 最终安装包
└── docs/             # 计划、构建及安装说明
```

### Windows 端

采用 Electron + React：

- 复用现有 React 控制台的设计语言和业务视图。
- 将页面、字体、图标和模拟数据全部内置。
- 支持无边框启动窗口、启动动画和窗口过渡。
- 使用安装程序创建桌面快捷方式。
- 启动时不出现终端窗口或浏览器地址栏。

### Android 端

采用 React/Vite + Capacitor：

- 不直接压缩桌面控制台，而是重构手机竖屏信息层级。
- 与桌面端共享品牌配置、图标和模拟数据。
- 最终生成可侧载安装的 Android APK。
- 最低目标 Android 9，优先适配 360×800、393×873、412×915 和 1080×2400。

## 四、视觉与交互设计

### 4.1 统一品牌体系

PC 和移动端共享：

- 应用名称“穗巡”。
- 已选定的麦穗、巡检道路、定位点和 DNA 双螺旋 Logo 语言。
- 深色科技农业主题。
- 青绿色、蓝色、金色及风险等级色。
- 孢子粒子、扫描光线、地图网格等视觉元素。
- 统一的应用图标和启动画面。

团队创始名称集中写入单一品牌配置文件，页面不散落硬编码；当前正式名称为“穗巡项目团队”。

### 4.2 启动过场动画

动画总时长控制在 2.5～3.5 秒：

1. 深色背景渐入。
2. 孢子粒子或扫描网格缓慢出现。
3. Logo 缩放并逐渐清晰。
4. “穗巡”应用名称分层浮现。
5. 显示团队署名。
6. 光线扫过 Logo，DNA 轨迹轻微流动。
7. 启动画面淡出，主控制台平滑进入。

要求无明显卡顿、白屏和闪屏；横屏与竖屏分别排版；动画资源全部内置。

### 4.3 Windows 主界面

整体延续现有 Web 控制台，包括：

- 顶部项目名称与系统状态。
- 功能导航。
- 地块与巡检路线地图。
- 环境监测数据。
- PCR 检测结果。
- 病害风险热力图。
- 3/5/7 天趋势预测。
- 机器人位置、电量、任务状态和雷达视图。
- 告警中心与任务概况。

所有数据固定为 `showcase/mock` 模式。按钮可以产生页面切换、弹窗、状态变化或图表更新，但不发送真实控制指令。

### 4.4 Android 主界面

移动端采用信息卡片与底部导航，一级导航精简为：

- 首页：风险等级、机器人状态、任务进度和核心数据。
- 巡检：简化地图、路线、当前位置和采样点。
- 分析：PCR 结果、病害判断和趋势预测。
- 项目：项目简介、团队信息和版本信息。

首页重点显示今日巡检状态、当前病害风险、PCR 最新结果、机器人电量、环境温湿度、预警数量和最近任务摘要。

## 五、实施阶段

### 阶段一：素材和代码基线整理

预计 0.5～1 个工作日：

- 确认品牌配置与页面清单。
- 提取现有 Web 控制台的颜色、字体、图标和组件语言。
- 建立独立多端展示工程。
- 固化展示用模拟数据。
- 隔离真实设备接口和敏感配置。

### 阶段二：公共品牌及启动动画

预计 1～2 个工作日：

- 制作横屏和竖屏启动画面。
- 实现 Logo、应用名称和团队署名动画。
- 生成 Windows 与 Android 图标。
- 完成启动页至主页面的无白屏切换。

### 阶段三：Windows 桌面端封装

预计 2～3 个工作日：

- 移植现有控制台设计语言。
- 接入本地模拟数据。
- 完成桌面窗口能力和常见分辨率适配。
- 配置并生成 Windows x64 安装包。

### 阶段四：Android 竖屏界面

预计 3～4 个工作日：

- 重构移动端信息架构。
- 制作首页、巡检、分析和项目信息页面。
- 适配竖屏、安全区域和全面屏。
- 添加卡片、数字、图表和页面切换动画。
- 封装 Android 工程并生成 APK。

### 阶段五：统一优化与验收

预计 1～2 个工作日：

- 验证完全离线运行。
- 检查启动速度、动画帧率和页面切换。
- 检查 Windows 安装、快捷方式和卸载。
- 在不同手机尺寸上验证布局。
- 清除调试入口、错误日志和敏感信息。
- 统一版本号、应用名称、图标和团队信息。
- 输出构建与安装说明。

整体预计工期为 8～12 个工作日。

## 六、验收标准

### Windows 端

- 可通过 `.exe` 正常安装和卸载。
- 安装后创建桌面快捷方式。
- 双击图标直接启动，不打开浏览器或终端。
- 启动过程无白屏、闪屏和明显卡顿。
- 无网络环境下所有展示页面正常显示。
- 主要按钮、导航、图表和弹窗具有反馈。
- 适配 1920×1080、1366×768 等常见分辨率。

### Android 端

- APK 可直接安装并正常启动。
- 竖屏布局无横向溢出和文字遮挡。
- 启动动画包含应用名称、Logo 和团队署名。
- 页面切换、滚动和卡片动画流畅。
- 无网络环境下可完整使用。
- 返回键、状态栏和全面屏安全区域处理正常。
- 应用重启后能够回到初始展示状态。

### 安全与边界

- 不包含系统密码、设备地址、SSH 信息或私密网络配置。
- 不向真实 `/cmd_vel` 或其他 ROS 控制主题发送消息。
- 不依赖 `HANDOVER.md` 等私密资料。
- 模拟数据与真实实验数据在代码层明确区分。
- 安装包中不包含无关日志、测试结果和大型厂商资料。
